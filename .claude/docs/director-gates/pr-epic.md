# PR-EPIC — 史诗结构可行性评审

Agent：`producer` | 模型层级：session（继承） | 领域：范围、时间线、依赖、制作风险

**触发时机**：`/create-epics` 定义完史诗之后、用户故事拆分出来之前——在调用
`/create-stories` 之前校验史诗结构是否可制作

**需传入的上下文**：
- 该层级的史诗结构，内联传入——每个史诗的范围摘要与管辖 ADR 数量。`/create-epics`
  在写入任何史诗文件*之前*运行本闸门，因此此时尚无路径。
- 里程碑时间线与目标日期
- 团队产能（单人 / 小团队 / 规模）
- 正在划史诗的层级（Foundation / Core / Feature / 等）

**提示词**：
> "在用户故事拆分开始前审查这套史诗结构的制作可行性。史诗边界划分是否恰当——
> 每个史诗是否有可能在某个里程碑截止前实际完成？史诗是否按系统依赖正确排序——
> 是否存在某个史诗在开始前需要另一个史诗的产出？是否存在范围过小的史诗（太小，
> 应合并）或范围过大的史诗（太大，应拆成 2-3 个聚焦的史诗）？Foundation 层史诗
> 的范围是否留出了空间，使 Core 层史诗能在 Foundation 完成后的下一个冲刺开始时
> 启动？返回 REALISTIC（史诗结构可制作）、CONCERNS [写用户故事前需要做的具体结构
> 调整]，或 UNREALISTIC [必须拆分、合并或重排史诗——解决前不能开始故事拆分]。"

**结论**：REALISTIC / CONCERNS / UNREALISTIC
