# /setup-engine — 第 7.5 节：搭建引擎项目脚手架

> 属于 `/setup-engine` 的一部分。`SKILL.md` 指明何时读取本文件；它解析出的
> 设置及其后续标题下的规则在此仍然适用。

## 7.5 搭建引擎项目脚手架

**没有这一步，框架会产出任何引擎都无法打开的源文件。**
`/dev-story` 会在解析出的代码根目录下写入 `.gd`/`.cs`/`.cpp`，而 `minimal` 路径
宣称"四步即可运行代码" — 但没有任何其他技能会为引擎写入
`project.godot`、Unity 项目或 `.uproject` 供其加载。

### Godot — 如果缺少 `project.godot` 就写入一个

**绝不要覆盖已有的 `project.godot`。** 如果文件已存在，
说明这一点并跳到第 8 节 — 开发者已有项目，其设置
归他们所有。

展示拟议的文件，然后询问：*"我可以在仓库根目录
创建 `project.godot` 吗？"* 获批后，写入：

```ini
config_version=5

[application]

config/name="<project name>"
config/features=PackedStringArray("<major.minor>", "<renderer feature>")

[rendering]

renderer/rendering_method="<rendering method>"
```

用已做出的决定填写 — 不要再次询问：

| 字段 | 来源 |
|-------|--------|
| `config/name` | 简报的工作标题，否则用仓库目录名 |
| `<major.minor>` | 第 3 节的 `engine.version`，仅主版本和次版本（`4.7.2` → `4.7`） |
| `<renderer feature>` / `<rendering method>` | 第 5.5.1 节选择的 `rendering` 值 — Compatibility → `"GL Compatibility"` / `gl_compatibility`；Forward+ → `"Forward Plus"` / `forward_plus`；Mobile → `"Mobile"` / `mobile` |

**保持 `run/main_scene` 未设置。** 在引擎设置阶段还没有场景。
添加一条注释，说明 `/dev-story` 或开发者会在场景存在后设置它；
没有主场景的空项目在编辑器中可以正常打开。

**然后验证，并报告验证实际做了什么。** 如果在第 3 节找到了引擎
二进制文件，运行其无头导入
（`godot --headless --path . --import`）并报告结果 — 读取输出中的
`ERROR`，因为即使项目中有内容加载失败，导入也会以 0 退出。在 Godot 4.7 上，
新项目的首次导入有时会在完成后以退出码
139 退出（退出时崩溃）；再运行一次并报告
第二次的结果。如果未找到二进制文件，或其版本与固定版本不同，写入
**`project.godot NOT VERIFIED — <reason>`**。`config_version` 和 feature
字符串在 Godot 4.x 各版本间是稳定的，但"在我所知的版本中稳定"并不等于
"已针对你固定的版本核查"，只有实际运行才能确立后者。

### Unity 和 Unreal — 指导，不要编造

Unity 项目和 `.uproject` 由编辑器生成，包含许多文件，
其中一些是二进制或机器相关的。本仓库无法取得它们的
正确内容，手写的脚手架正是第 7 节取材来源规则所禁止的失败 —
看起来已完成，却悄悄出错。

用一小段话告诉用户，CCGS 不会为这些引擎创建项目，
他们应先自行创建：

- **Unity** — 在仓库根目录通过 Unity Hub 创建项目，选择与
  第 2 节的 2D/3D 答案匹配的模板，然后重新运行 `/setup-engine`。
- **Unreal** — 在 Epic 启动器中或通过 `UnrealEditor` 创建项目，
  然后重新运行。

无论如何都要在第 12 节摘要中报告结果 — 已创建、已存在，
或"未创建，引擎需要编辑器" — 以便用户离开本技能时
知道是否存在可运行的项目。

> **有意不设为 `project.yaml` 键。** `engine.project_scaffolded` 标志
> 会在这里写入，却不会被任何东西读取，这是一个死设置 —
> 正是配置闸门（gate）要捕获的有写无读缺陷。文件系统
> 才是事实来源：任何需要知道的技能直接匹配 `project.godot`、
> `*.uproject` 或 `ProjectSettings/ProjectVersion.txt` 即可。
