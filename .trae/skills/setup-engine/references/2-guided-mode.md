# /setup-engine — 第 2 节：引导模式

> 属于 `/setup-engine` 的一部分。`SKILL.md` 指明何时读取本文件；它解析出的
> 设置及其后续标题下的规则在此仍然适用。

## 2. 引导模式（无参数）

**本文件内容：**

- 检查是否已有游戏概念
- 如果用户希望在没有概念的情况下选择，按此顺序提问
- 产出推荐

如果未指定引擎，运行交互式引擎选择流程：

### 检查是否已有游戏概念
按小节读取当前层级对应的设计产出物（见上文 **层级感知（Tier awareness）**）：用 Grep 工具（pattern `^#`，content 模式）
找到你需要的标题，再用 offset 和 limit 读取这些范围：
- **`standard` / `full`**：如果 `design/gdd/game-concept.md` 存在，读取它 —
  提取类型、范围、目标平台、美术风格、团队规模，以及
  `/brainstorm` 记录的引擎偏好（用户指定的引擎，或 "undecided"：
  `/brainstorm` 从不推荐引擎，因此推荐在此处做出）。
- **`minimal`**：如果 `design/game-brief.md` 存在，读取它 — 从其字段中提取类型、
  范围、平台和美术方向。在 `minimal` 下它缺失是**预期内**的
  （在 minimal 路径中，简报是在引擎配置*之后*撰写的），因此
  不要把缺失的简报当作缺口 — 直接进入引导式选择。
- 如果概念**和**简报都不存在，告知用户：
  > "未找到游戏概念。可考虑先运行 `/brainstorm` 来发现你
  > 想构建的内容 — 如果你有引擎偏好，它会记录下来。或者
  > 告诉我你的游戏，我可以帮你选择。"

  （在 `minimal` 下这是可选的，不是前置条件 — 你现在就可以选引擎，
  然后写简报。）

### 如果用户希望在没有概念的情况下选择，按此顺序提问：

**问题 1 — 既往经验**（始终首先询问，通过 `AskUserQuestion`）：
- 提示："你以前用过以下引擎吗？"
- 选项：`Godot` / `Unity` / `Unreal Engine 5` / `Multiple — I'll explain` / `None of them`
- 如果他们选择某个具体引擎 → 推荐该引擎。既往经验胜过所有其他因素。与他们确认并跳过矩阵。
- 如果选 "None" 或 "Multiple" → 继续下面的问题。

**问题 2-6 — 决策矩阵输入**（仅当没有既往引擎经验时）：

**问题 2 — 目标平台**（始终第二个询问，通过 `AskUserQuestion` — 平台会在任何其他因素之前排除或大幅影响引擎的权重）：
- 提示："这款游戏你面向哪些平台？"
- 选项：`PC (Steam / Epic)` / `Mobile (iOS / Android)` / `Console` / `Web / Browser` / `Multiple platforms`
- 直接影响推荐结果的平台规则：
  - Mobile → 强烈推荐 Unity；Unreal 不太适合；Godot 对于简单的移动游戏可行
  - Console → Unity 或 Unreal；Godot 的主机支持需要第三方发行商或大量额外工作
  - Web → Godot 可以干净地导出到 web；Unity WebGL 可用；Unreal 的 web 支持较差
  - 仅 PC → 所有引擎都可行；由其他因素决定
  - 多平台 → Unity 在 PC/移动/主机之间可移植性最强

1. **做哪种游戏？**（2D、3D，还是两者都做？）
2. **主要输入方式？**（键盘/鼠标、手柄、触摸，还是混合？）
3. **团队规模和经验？**（单人新手、单人老手、小型团队？）
4. **有强烈的语言偏好吗？**（GDScript、C#、C++、可视化脚本？）
5. **引擎授权的预算？**（只用免费，还是可以接受商业许可？）

### 产出推荐

不要使用会排除引擎的简单评分矩阵。相反，结合下面的真实取舍来推理
用户的画像，然后给出 1-2 个带完整背景的推荐。始终以用户做选择收尾 — 绝不要强加结论。

**引擎的真实取舍：**

**Godot 4**
- 真正的优势：2D（同类最佳）、风格化/独立 3D、快速迭代、永久免费（MIT）、开源、学习曲线最平缓、最适合希望完全掌控的单人开发者
- 真实局限：3D 生态相比 Unity/Unreal 较为薄弱（针对 3D 问题的教程、资源、社区答案更少）；大型开放世界 3D 非常困难且在 Godot 中基本未经检验；主机导出需要第三方发行商或大量额外工作；专业就业市场较小
- 授权现实：真正免费，永远没有收入门槛。MIT 许可证意味着你拥有一切。
- 最适合：任何规模的 2D 游戏；风格化/氛围化 3D；封闭式 3D 世界（非开放世界）；学习曲线重要的首个游戏项目；任何规模下预算都是硬约束的项目

**Unity**
- 真正的优势：中等规模 3D 和移动领域的行业标准；庞大的资源商店和教程生态；C# 是专业语言；对独立开发者而言主机认证支持最佳；几乎所有品类都有强大的社区
- 真实局限：2023 年的授权争议损害了信任（运行时费用被提出后又撤回 — 政策变化的风险依然真实）；C# 的初始学习曲线比 GDScript 更陡；对于简单项目，编辑器比 Godot 更重
- 授权现实：在收入低于 20 万美元**且**安装量低于 20 万时免费（Unity Personal/Plus）。只有游戏真正成功时才会变得昂贵 — 大多数独立游戏永远达不到这个门槛。2023 年的争议值得了解，但当前的实际条款对大多数独立开发者来说是合理的。
- 最适合：移动游戏；中等规模 3D；面向主机的游戏；有 C# 背景的开发者；需要大型资源商店的项目；2-5 人的团队

**Unreal Engine 5**
- 真正的优势：同类最佳的 3D 视觉（Lumen、Nanite、Chaos 物理）；AAA 和照片级写实 3D 的行业标准；大型开放世界支持成熟且经过生产验证；Blueprint 可视化脚本降低了 C++ 门槛；适合面向高端 PC 或主机的游戏
- 真实局限：学习曲线最陡；编辑器最重（编译时间长、项目体积大）；对于风格化/2D/小规模游戏属于杀鸡用牛刀；C++ 确实很难；不适合移动或 web；总收入超过 100 万美元后收取 5% 分成
- 授权现实：5% 分成仅在单款作品总收入**超过** 100 万美元后才适用。对于第一款游戏或任何达不到 100 万美元的游戏，它不花分文。这个门槛足够高，大多数独立开发者永远不会支付。
- 最适合：AAA 品质的 3D；大型开放世界游戏；照片级写实视觉；有 C++ 经验或愿意使用 Blueprint 的开发者；面向高端 PC/主机且视觉保真度是核心卖点的游戏

**按品类的指导**（将其纳入推荐考量）：
- 任何风格的 2D → 强烈推荐 Godot
- 3D 风格化 / 氛围化 / 封闭世界 → Godot 可行，Unity 是可靠的替代方案
- 3D 开放世界（大型、无缝）→ Unity 或 Unreal；Godot 在此尚未经过生产验证
- 3D 照片级写实 / AAA 品质 → Unreal
- 移动优先 → 强烈推荐 Unity
- 主机优先 → Unity 或 Unreal；Godot 的主机支持需要额外工作
- 恐怖 / 叙事 / 步行模拟 → 任何引擎；与美术风格和团队经验相匹配
- 动作 RPG / 类魂 → 3D 用 Unity 或 Unreal；社区支持和资源在这里很重要
- 2D 平台跳跃 → Godot
- 策略 / 俯视 / RTS → 视 2D 还是 3D 选择 Godot 或 Unity

**推荐格式：**
1. 展示一张以用户具体因素为行的对比表
2. 给出主要推荐并附上诚实的推理
3. 指出最佳替代方案以及何时应改选它
4. 明确说明："这是一个起点，而非结论 — 你随时可以迁移引擎，许多开发者会在不同项目之间切换。"
5. 使用 `AskUserQuestion` 确认："这个推荐感觉合适吗，还是你想探索其他引擎？"
   - 选项：`[Primary engine] (Recommended)` / `[Alternative engine]` / `[Third engine]` / `Explore further` / `Type something`

**如果用户选择 "Explore further"：**
使用 `AskUserQuestion`，提供针对概念的深入探讨主题。始终根据用户的实际概念生成这些选项 — 不要使用通用选项。至少始终包含：
- 主要引擎针对该概念的具体局限（例如 "Godot 3D 对 [类型] 究竟能做到什么程度？"）
- 替代引擎针对该概念的具体取舍
- 语言选择对该概念技术挑战的影响
- 任何针对该概念的技术关注点（例如自适应音频、开放世界流式加载、多人网络代码）

用户可以选择多个主题。在回到引擎确认问题之前，深入回答每个选中的主题。
