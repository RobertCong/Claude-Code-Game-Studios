# 原型代码标准（放宽）

原型是用于验证想法的丢弃型代码。标准被刻意放宽，以最大化迭代速度。目标是学习，而不是生产质量。

## 原型中允许的做法
- 硬编码数值（无需数据驱动配置）
- 最少或没有文档注释
- 简单架构（不需要依赖注入）
- 单例和全局状态
- 复制粘贴的代码（无需抽象）
- 保留调试输出
- 占位美术和音频
- 快速粗糙的解决方案

## 仍然必须遵守
- 每个原型位于自己的子目录：`prototypes/[name]/`
- 每个原型必须有 `README.md`，包含：
  - 正在测试什么假设
  - 如何运行该原型
  - 当前状态（进行中 / 已结束）
  - 发现（原型结束时更新）
- 生产代码不得引用或导入 `prototypes/`
- 原型不得修改 `prototypes/` 之外的文件
- 原型不得部署或发布

## 原型成功时
如果一个原型验证了概念，功能进入生产：
1. 原型代码不会被直接迁移——而是按生产标准重写
2. 原型 `README.md` 的发现用于指导生产设计文档
3. 原型目录保留作参考，但绝不再扩展

## 清理
已结束的原型在记录发现后应归档或删除。绝不要让原型代码通过渐进式「清理」长成生产代码。
